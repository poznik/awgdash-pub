# awgdash

Лёгкая панель управления серверами [AmneziaWG](https://amnezia.org): пользователи и их устройства,
персональные ссылки с QR и `.conf`, статистика трафика, оповещения в Telegram, шифрованные
резервные копии и управление несколькими серверами из одного места.

Один статический бинарник на Go, база SQLite, никаких внешних сервисов. Интерфейс — на русском.

Панель **не владеет туннелями**: интерфейс поднимает systemd (`awg-quick@<имя>`), панель правит
только пиров. Остановка или падение панели на работающие подключения не влияет.

## Возможности

- **Пользователи и устройства.** У человека несколько устройств, у устройства — свой сервер.
  Ключи генерируются в панели, конфиг выдаётся с QR и файлом `.conf`, есть пресеты для телефона
  и роутера и ручная настройка.
- **Портал самообслуживания.** Персональная ссылка `/u/<токен>`: человек видит свои устройства,
  скачивает конфиг и, если разрешено, добавляет и удаляет устройства сам.
- **Статистика.** Трафик за сутки, неделю, месяц и всё время по устройству, человеку, интерфейсу
  и серверу; графики без сторонних библиотек; метрики машины (диск, память, нагрузка).
- **Парк серверов.** Хаб управляет удалёнными узлами через ssh-туннель; история трафика
  переживает разрывы связи.
- **Telegram.** Падение интерфейса или узла, пропажа рукопожатий, первое подключение устройства,
  пороги диска и памяти — с дайджестом, тихими часами и подавлением повторов.
- **Резервные копии.** База, конфиги интерфейсов и `.env` в одном файле, зашифрованном
  [age](https://age-encryption.org); восстановление на другой машине с переписыванием правил NAT.
- **Вход.** Пароль (argon2id) с TOTP или ключ доступа (passkey, WebAuthn).
- **Импорт** пиров из WGDashboard и wg-easy без перевыпуска ключей.

## Как устроено

Один бинарник работает в одной из двух ролей (`AWGDASH_MODE`):

| роль | что делает |
|---|---|
| `hub` | веб-панель, портал, база, опрос парка, оповещения, копии; он же узел для своей машины |
| `node` | только агент на удалённом сервере: читает и пишет пиров, отдаёт выборки по API `/v1/*` |

Оба слушают только loopback. Админка и портал публикуются обратным прокси, узел достижим для хаба
через ssh-туннель (`deploy/awgdash-tunnel@.service`).

У каждого интерфейса два режима:

- **наблюдение** (`observe`) — панель только читает состояние и считает трафик;
- **управление** (`own`) — панель единственный писатель пиров: сначала файл конфигурации, затем
  `awg set`, затем сверка параметров обфускации с ядром.

Перед записью панель проверяет, что на интерфейсе нет чужого менеджера пиров
(`AWGDASH_FOREIGN_MANAGERS`), и отказывается писать, если он активен.

## Требования

- Linux с systemd, модуль ядра AmneziaWG и утилиты `awg`, `awg-quick`;
- интерфейс уже поднят: `awg-quick@<имя>`, конфиг в `/etc/amnezia/amneziawg/`;
- Go 1.26+ для сборки;
- обратный прокси с TLS перед панелью.

## Сборка и установка

```bash
git clone https://github.com/poznik/awgdash-pub.git && cd awgdash-pub
go test ./...
make build            # dist/awgdash, linux/amd64
```

Установка на сервер по ssh (нужен `sudo` без пароля):

```bash
make deploy HOST=<ssh-алиас>
```

`make deploy` копирует бинарник и юнит, запускает `deploy/install.sh`: тот заводит пользователя
`awgdash`, каталоги `/opt/awgdash`, `/var/lib/awgdash`, `/etc/awgdash`, при первом запуске создаёт
`/etc/awgdash/awgdash.env` со случайными секретами и включает `awgdash.service`. Список машин
можно записать в файл `.awgdash-hosts` (по алиасу в строке, хаб последним) — тогда `make deploy`
обновляет весь парк.

Первый администратор:

```bash
sudo systemd-run --quiet --wait --pipe --collect --uid=awgdash --gid=awgdash \
  -p EnvironmentFile=/etc/awgdash/awgdash.env /opt/awgdash/awgdash admin create <имя>
```

Пароль печатается один раз. Затем задайте внешние имена в `AWGDASH_ADMIN_HOST` и
`AWGDASH_PORTAL_HOST`, перезапустите сервис и направьте на `127.0.0.1:10088` обратный прокси.

## Настройка

Все параметры — переменные окружения в `/etc/awgdash/awgdash.env` (права `0600`). Шаблон с
пояснениями — [.env.example](.env.example). Главное:

| переменная | назначение |
|---|---|
| `AWGDASH_MODE` | `hub` или `node` |
| `AWGDASH_LISTEN` | адрес слушателя, по умолчанию `127.0.0.1:10088` |
| `AWGDASH_ADMIN_HOST`, `AWGDASH_PORTAL_HOST` | имена, на которые отвечают админка и портал |
| `AWGDASH_FORWARDED_HOPS` | число обратных прокси перед панелью: адрес клиента берётся с хвоста `X-Forwarded-For` |
| `AWGDASH_SESSION_KEY` | ключ сессий, `openssl rand -base64 32` |
| `AWGDASH_NODE_TOKEN` | токен API узла, общий для хаба и узлов |
| `AWGDASH_FOREIGN_MANAGERS` | чужие менеджеры пиров: юнит systemd или `docker:<контейнер>` |
| `AWGDASH_TELEGRAM_TOKEN`, `AWGDASH_TELEGRAM_ADMIN_IDS` | бот и белый список получателей |
| `AWGDASH_AGE_RECIPIENT` | публичный ключ `age` для копий; без него копии не делаются |
| `AWGDASH_TZ` | часовой пояс расписаний и тихих часов, по умолчанию `UTC` |

## Удалённый узел

1. Поставьте панель на второй сервер с `AWGDASH_MODE=node`, `AWGDASH_LISTEN=127.0.0.1:10089`
   и тем же `AWGDASH_NODE_TOKEN`, что на хабе.
2. На хабе положите ssh-ключ в `/etc/awgdash/keys/<слаг>`, параметры туннеля — в
   `/etc/awgdash/tunnels/<слаг>.env` (формат описан в `deploy/awgdash-tunnel@.service`) и включите
   `awgdash-tunnel@<слаг>.service`. На узле ограничьте ключ:
   `restrict,port-forwarding,permitopen="127.0.0.1:10089"`.
3. Заведите узел в реестре: `awgdash server add --slug <слаг> --port 10089 --country <код>`.

## Команды

```
awgdash [hub|node]                       запуск; без аргумента роль берётся из AWGDASH_MODE
awgdash admin create|passwd|totp|reset-totp|delete|list
awgdash server add|list|check|set|enable|disable|retire|return|rm
awgdash mode --interface <имя> [--set own|observe]
awgdash reconcile --interface <имя> [--dry-run]
awgdash import wgdashboard|wg-easy --interface <имя> [--dry-run]
awgdash backup now [--full] | list | verify <файл> | keygen [--install]
awgdash restore <файл> [--age-key <файл>] [--dry-run] [--yes] [--no-start] [--drill] [--server <слаг>]
awgdash purge [--older <дней>] [--dry-run]
awgdash doctor                           проверка окружения
awgdash version
```

Команды, которые читают или пишут конфиг интерфейса (`mode`, `reconcile`, `import`), запускаются
с теми же правами, что и сервис: к `systemd-run` из примера выше добавляется
`-p AmbientCapabilities="…"` со списком из `deploy/awgdash.service`.

## Безопасность

- Слушатель — только loopback; наружу панель выходит через обратный прокси с TLS.
- API узла `/v1/*` регистрируется только в режиме `node` и закрыт токеном; публиковать его
  в интернет не нужно.
- Конфиг интерфейса остаётся `root:0600`, прежняя версия сохраняется перед каждой записью.
- Приватные ключи и PSK не попадают в журнал аудита и события.
- Копии шифруются; приватный ключ `age` на сервере не хранится.

## Разработка

```bash
go test ./...                 # тесты не требуют AmneziaWG: awg подменён моделью internal/awgtest
make vet
```

Стенд с синтетическими данными для осмотра интерфейса:

```bash
AWGDASH_STAND_PORT=8088 go test ./internal/web -tags devserver -run TestDevServer -timeout 60m -v
```

Проверка записи в настоящий интерфейс — на тестовом `awg-t0` в отдельном сетевом пространстве
имён, боевые интерфейсы не затрагиваются: `deploy/awg-t0.sh`.

Структура: `cmd/awgdash` — точка входа и CLI; `internal/awg` — разбор и запись конфигов, сверка;
`internal/node` и `internal/nodeclient` — агент узла и его клиент; `internal/hub` — циклы опроса
и сервисы; `internal/store` — SQLite и миграции; `internal/web` — админка и портал;
`internal/backup`, `internal/telegram`, `internal/auth`, `internal/importer` — по названию.
